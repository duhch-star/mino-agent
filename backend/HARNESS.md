# MINOS 文件工具 Harness

## 使用

登录后，在对话助手中发送例如：

> 请在工作区创建 interview-plan.md，写一份三天面试准备清单，然后读回来确认。

模型通过 OpenAI 兼容 `tools/tool_calls` 协议自主选择工具，执行结果作为 `role=tool` 返回模型，直至回答完成。不是根据关键词伪造工具记录，也不是将工具名称注入提示词后假装执行。供应商必须支持流式工具调用。

界面中的每次调用均可折叠，展开查看入参、输出/错误、状态和耗时。登录会话的调用记录保存在消息 metadata 中，重新打开历史仍可查看。模型内部推理不属于公开工具轨迹，不展示。

## 工具

- `list_files(path='.')`：列出目录，最多 200 项。
- `read_file(path, offset=1, limit=100)`：读取 UTF-8 文本，返回行号。
- `write_file(path, content)`：只创建新文件，禁止直接覆盖。
- `edit_file(path, old_text, new_text)`：精确替换唯一匹配文本，本轮必须先读取。
- `search_files(query, path='.')`：普通字符串搜索，最多扫描 200 个文件、200 个目录并返回 40 条命中。

## 边界

- 必须登录；以用户 ID 的哈希划分 `app/workspaces/` 下的独立工作区。
- 不允许绝对路径、上级路径、隐藏配置文件、Windows 设备名、符号链接或目录联接。
- 文件不超过 128 KiB，只处理 UTF-8 文本；读取输出有长度上限。
- 单轮最多 6 轮模型响应、12 次工具执行。达到限制则报错，已完成的文件操作不会回滚。
- 不提供 shell、删除、任意主机文件系统访问或网络执行工具。
- 模型失败明确报告，不静默伪装成 Mock 成功。未配置模型时保持原演示模式，不伪造工具调用。
- 停止前端请求不能保证撤回已发送的模型请求或后台线程中的文件写入，操作后可重新读取确认。
- 这是应用级工作区限制，不是操作系统安全沙箱；不要允许不可信本机程序修改工作区符号链接。公网部署还需要 OS 隔离、请求限速、并发控制及写操作审批等加强措施。

## 回归测试

在 backend 目录运行：

```powershell
..\.venv\Scripts\python.exe -m unittest test_harness -v
```

覆盖文件操作、路径边界、覆盖保护、歧义替换、模型多轮工具调用、错误回传、先读后改及轮数上限。
